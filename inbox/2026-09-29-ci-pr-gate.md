# CI a PR-en, a merge-et a `/merge` tiltja

## Mi

A CI (GitHub Actions) csak PR-en fut (`on: pull_request`), ugyanazokkal a
parancsokkal, mint a `/commit` pre-commit gate-je (+ build); a `/merge` a
`gh pr checks` alapján megáll, ha a CI nem zöld. A CI-sablon stack-specifikus
→ a stack skilljébe/pluginjébe kerül, nem a `workflow.md`-be.

## Miért

- A lokális gate azon múlik, hogy az *AI* lefuttatja-e és helyesen jelenti-e;
  a CI eredménye tény, tiszta környezetben (lockfile-ból install, nincs lokális
  `.env`, nincs globális eszköz).
- A `pull_request` trigger a merge-eredményt teszteli (`refs/pull/N/merge`),
  így a `main` munka közbeni behúzása nélkül is kiderül, ha az ág a friss
  `main`-nel törik.
- GitHub-szintű tiltás (branch protection / ruleset, „Require status checks”)
  privát repón Free csomagon nem érhető el — a `claude-plugins` repón:
  ```
  Upgrade to GitHub Pro or make this repository public to enable this feature. (HTTP 403)
  ```
  A *Fejlesztő* döntése: egyelőre a `/merge`-ben tiltunk (2. opció), Pro nem kell.
- CD marad Continuous Delivery: kézi `/release`, a `main` auto-deploy kikapcsolva.

## Hogyan alkalmazd

- **Stack-skill**: `.github/workflows/ci.yml` sablon, `on: pull_request`; a
  `/merge` a merge előtt `gh pr checks` → nem zöld vagy még fut → **állj meg**.
  `--admin` merge soha.
- **Fix-jellegű munka** (`dev` → `main`, PR nélkül): a CI `on: push: branches: [dev]`
  triggerrel is fusson — PR a `dev`-ről nem kell (döntés: 2026-09-29). A `/merge` B
  ága a fast-forward előtt a `dev` HEAD futását nézi (`gh run list --branch dev --commit <sha>`).
- **„Require branches to be up to date”**: ne — ütközik azzal, hogy a `main`
  munka közben nem kerül az ágba. Megszorítás: ha a PR nyitása után a `main`
  elmozdul, a check magától nem fut újra.
- **Monorepo**:
  - pnpm workspace: egy job, csak az érintett csomagok és függőik:
    `pnpm -r --filter "...[origin/main]" run <script>` (a `fetch-depth: 0`
    kell a checkoutnál). Turbo esetén `turbo run ... --affected`.
  - Vegyes stack (pl. `apple/` Swift + `pwa/`): külön job részenként,
    `paths:` szűrővel. A Swift job macOS runnert kér — privát repón a macOS
    perc 10×-es szorzóval fogy a Free keretből; érdemes csak az `apple/**`
    változásra futtatni.
  - Ha később GitHub-szintű kötelező check lesz: a `paths:` miatt ki nem
    futott workflow checkje „pending” marad és blokkol — ilyenkor job-szintű
    szűrés (pl. `dorny/paths-filter`) kell, nem workflow-szintű.
- **Nyitott**: a PR-leírás `## Élesítés` és `## Ellenőrzés` szakasza
  (a deployhq PR-cikk alapján), és hogy a `/release` gyűjtse az Élesítés-szakaszokat.
