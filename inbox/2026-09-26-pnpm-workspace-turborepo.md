## Mi

Vercel/Node projektben a csomagkezelő mindig pnpm, pinelt `packageManager` + `engines.node` mezővel. Monorepóhoz pnpm workspace kell; Turborepót csak konkrét ok esetén használunk. A pnpm önállóan (Homebrew) fut, nem Corepack-en át, és a globális csomagokat is a pnpm kezeli.

## Miért

- A „pnpm vagy turborepo?” kérdés hamis dilemma: a pnpm csomagkezelő (és workspace), a Turborepo pedig task-runner/cache egy workspace *fölött*. A tényleges döntés: egy csomag → pnpm workspace → workspace + Turbo.
- 10 Vercel-es projekt áttekintése után egyiknél sem lett volna ideális a Turbo:
  - `package-monitor` (pakkly): pnpm workspace (`apps/api`, `apps/web`, `packages/core`) + Vercel Services, egy projekt, egy deploy. Build-lépése csak a `web`-nek van → a Turbónak nincs mit cache-elnie; a `pnpm -r` / `--filter` elég.
  - `Manas2026`, `MicrOasis2026`: `apple/` (Swift) + `pwa/` → a Turbo a Swift-részt nem látja, semmit nem nyerne.
- Két tényleges hiba derült ki:
  - 3 projekt npm-et használ (`varazskez/hangfurdo`, `Fertőszentmiklós/web`, `Torma.AI` — `package-lock.json`), holott az npm kizárt.
  - 5 pnpm-es projektből hiányzik a `packageManager` mező (`Manas2026/pwa`, `MicrOasis2026/pwa`, `nuxt-framework`, `super-test/nuxt-app`, `varazskéz-hangfürdő`).
- **`packageManager` nélkül a Vercel és a lokális gép más pnpm-et futtat.** A MicrOasis2026 build logja:
  ```
  Detected `pnpm-lock.yaml` 9 which may be generated by pnpm@9.x or pnpm@10.x
  Using pnpm@10.x based on project creation date
  Done in 1.4s using pnpm v10.28.0
  ```
  Lokálisan közben 11.1.3 futott, mert egy `~/package.json` (`packageManager: pnpm@11.1.3`) minden pin nélküli projektet elfedett — a Corepack felfelé keres a könyvtárfában. Ezt a fájlt töröltük.
- **Pinnel a Vercel pontosan azt futtatja** (docs táblázata elavult, szerinte csak pnpm 6–10 támogatott):
  ```
  Detected `pnpm-lock.yaml` version 9 generated by pnpm@12.x from package.json#packageManager pnpm@12.6.0
  Done in 5.5s using pnpm v12.6.0
  ```
  A pnpm 12.6.0-t a `vercel-neon-test`-en teszteltük, buildcache-sel és `vercel deploy --force`-szal (cache nélkül) is: zöld. A pnpm 12 a lockfile elejére egy `packageManagerDependencies` YAML-dokumentumot tesz, a `lockfileVersion` marad `9.0` — a Vercel kezeli.
- **Corepack helyett önálló pnpm:** a Corepack a Node 25-től nincs a Node-ban; a pnpm 11+ maga is letölti és futtatja a `packageManager`-ben rögzített verziót (`pmOnFail: download` az alapérték). Nincs szükség `ENABLE_EXPERIMENTAL_COREPACK`-ra sem.
- **Csapdák a lokális átállásnál:**
  - `npm rm -g corepack` a Homebrew-s pnpm `pnpm`/`pnpx` symlinkjét is törli (a Corepack `bin` listája tartalmazza őket). Javítás: `brew unlink pnpm && brew link pnpm`.
  - A Homebrew `node@24` minden linkeléskor/frissítéskor visszarakja a Corepack-et (`/opt/homebrew/bin/corepack`) — ez rendben van, amíg nincs `corepack enable` (nincsenek pnpm/yarn shimek).
  - `pnpm setup` meglévő pnpm-blokknál `ERR_PNPM_BAD_SHELL_SECTION`-nel megáll, de közben feltesz egy saját `@pnpm/exe`-t a `PNPM_HOME/bin`-be (Homebrew-s pnpm mellett ez duplikátum, és build-script nélkül hibás). Leszedni: `pnpm rm -g @pnpm/exe`.
  - A pnpm 11+ a globális binárisokat a `$PNPM_HOME/bin`-be teszi (nem a `$PNPM_HOME`-ba) — a `.zshrc` PATH-blokkját erre kell igazítani, különben `ERR_PNPM_GLOBAL_BIN_DIR_NOT_IN_PATH`.
  - A pnpm 11+ globális telepítései izolált csoportok (`global/v11/<hash>/`): a `typescript-language-server` nem látja a külön telepített `typescript`-et → egy csoportba kell tenni: `pnpm add -g typescript-language-server@X typescript@Y`.
  - A pnpm 11+ a build-scripteket alapból blokkolja globálisan is. Az `ngrok` nélküle nem működik (`Bad CPU type in executable`) → `pnpm add -g --allow-build=ngrok ngrok`; `esbuild`-függő CLI-knél (`neon`, `vercel`) `--allow-build=esbuild`.
  - `pnpm add -g <pkg>` a legfrissebbet teszi fel — npm-ről átköltöztetésnél pontos verzióval (`<pkg>@<npm-es verzió>`) kell, különben észrevétlen főverzió-ugrás jön (itt: TS 5→7, pm2 6→7, vercel 59→60).

## Hogyan alkalmazd

A `stack.md`-be (vagy a `vercel-neon` bootstrapbe) javasolt sorok:

```
- **Csomagkezelő**: pnpm (önálló, Homebrew; nem Corepack), `packageManager` + `engines.node: "24.x"` mindig a package.json-ban.
- **Globális CLI-k**: `pnpm add -g`, nem `npm i -g`.
- **Monorepo**: pnpm workspace, ha több deployolható rész vagy közös csomag van.
- **Turborepo**: csak ha (a) több Vercel projekt jön egy repóból (→ `turbo-ignore` az érintetlen deployok kihagyására), vagy (b) a build/test annyira lassú, hogy megéri a cache (lokális + Vercel Remote Cache). Addig `pnpm -r` / `--filter`.
```

- Új projekt bootstrapnél: `packageManager` és `engines.node` az első commitban.
- Meglévő projekt érintésekor: ha `package-lock.json` van, vagy hiányzik a `packageManager`, jelezd a *Fejlesztő*nek — pin nélkül a Vercel más pnpm főverzióval buildelhet, mint a lokális gép.
- Pin nélküli projektben ne futtass `pnpm install`-t a pin pótlása előtt: az újabb lokális pnpm átírhatja a lockfile-t.
- Turbo 2.x-ben a `turbo.json` kulcsa `tasks` (az 1.x-es `pipeline` elavult) — a régi `WSL/turborepo` még `pipeline`-t használ.
